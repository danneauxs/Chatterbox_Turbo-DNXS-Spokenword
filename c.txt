
Current throughput is ~3-4x real-time (1 min compute → 3-4 min audio). Goal is 8-10x.
The `config/config.py` file has dozens of speed-related toggles (`ENABLE_TORCH_COMPILE`,
`ENABLE_FP16_PRECISION`, `ENABLE_TF32_MATMUL`, `ENABLE_BATCH_BINNING`, etc.) but an audit
of the actual code shows most are either dead (never read, or read under the wrong name),
duplicated, or contradicted by hardcoded behavior elsewhere. The real speed levers are a
short, different list from what the config file implies. This plan documents what's
actually true today, what's fake, and what to change to close the gap to 8-10x.

**Confirmed by code + a `resemble-ai/chatterbox` maintainer/community issue
([#193](https://github.com/resemble-ai/chatterbox/issues/193)) and web research on
CosyVoice2 (S3Gen's origin) and Chatterbox-Turbo's own release notes.**

### What's already working (don't touch / don't re-implement)
- **S3Gen diffusion steps already cut from 10 → 2** via `meanflow=True` +
  `n_cfm_timesteps=2` hardcoded at `src/chatterbox/tts_turbo.py:236,560`. This is the
  single biggest lever discussed in community threads (going 10→2-3 steps cuts mel
  generation ~8-10x on its own) — **already applied**. No further gain available here
  without quality loss.
- T3 KV-cache is used correctly (`past_key_values` passed each decode step,
  `t3.py:497-536`), and the generated-id tensor grows via `torch.cat` once per step
  (already noted in-code as O(n) not O(n²)).
- FP16 for T3, FP32 for VoiceEncoder/S3Gen (stability), TF32 matmul — all genuinely
  wired in `tts_turbo.py:190,205,224-227,244,260`.
- `torch.compile` on `t3.tfmr` is genuinely active when `ENABLE_TORCH_COMPILE=True`
  (`tts_turbo.py:232-234`).
